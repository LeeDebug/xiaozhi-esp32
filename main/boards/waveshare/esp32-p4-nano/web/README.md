# Modbus Lab · ESP32-P4 Nano 从机模拟器

纯静态网页，无 npm 安装、无外部 CDN、无后台服务。电脑通过 Web Serial 扮演产线设备，P4 固件继续作为主站。

## 启动

在仓库根目录执行：

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory main/boards/waveshare/esp32-p4-nano/web
```

用桌面 Chrome 或 Edge 打开 <http://127.0.0.1:8765>，点击「连接串口」并选择连接业务 UART1 / RS485 总线的 USB 适配器。默认从机地址 **1**、波特率 **9600**、格式 **8N1**，与当前固件一致。页面使用 ES Modules，请通过 HTTP 访问，不要直接双击 HTML。Web Serial 需要支持该 API 的浏览器和安全上下文（localhost / HTTPS）。[Chrome 官方 Web Serial 文档](https://developer.chrome.com/docs/capabilities/serial)。

停止服务器：在运行命令的终端按 Ctrl+C。串口同时只能由一个应用占用，连接前关闭占用该适配器的串口助手。

## 接线与使用

- 固件业务口为 **UART1，TX GPIO20，RX GPIO21**，不是开发板下载 / 日志串口。
- RS485 方案：板端自动方向控制收发器接 UART1，USB-RS485 接电脑，双方 A/B 对接、按模块要求共地。电脑适配器也需自动方向切换，关闭本地回显。板端未配置 DE/RE GPIO。
- 直接 TTL 方案：仅当板端接口确实是 3.3V UART 时，适配器 RX 接 GPIO20，TX 接 GPIO21，并共地。不可将 A/B 接 GPIO。
- 保持页面前台，修改模拟值后失焦提交；收到 `03` 请求时返回当前值，收到 `06` 请求时更新寄存器并回显确认。广播 `06` 更新数据但不响应；CRC 错误、其他地址不响应。
- 固件的 `kAutomaticPollingEnabled=false`，连接后没有流量是正常现象。需通过现有 MCP 工具主动触发读取、开关灯或水阀操作。
- 开关水阀工具会先 `03` 读取旧状态，再 `06` 写入新状态。灯光设置只发送 `06`。料塔工具依次读取 4 对寄存器。
- 「离线试报文」无需硬件，将请求填入输入框后点「解析并模拟」。不会向真实串口发数据，离线写入会改变共享的模拟寄存器；离线记录带标签且不计入真实收发统计。
- 自动响应关闭时只监视报文，不执行写入。响应延迟可设 0–3000ms；固件响应超时为 1000ms，延迟超时可能导致主站重试和迟到响应，仅供故障模拟。响应按顺序排队，最多 64 条，断开后取消待发数据。

## 源码分析与寄存器映射

依据本目录上级的 `production_modbus.cc/.h`、`production_mcp_tools.cc`、`config.h` 与 `esp32-p4-nano.cc`：

- `ProductionModbus::Start()` 初始化 9600-8N1 RTU 主站，响应超时 1000ms，UART 为普通 UART 模式，依赖外部自动收发切换。
- 单例默认地址 0 表示禁用；**板卡构造函数启动后设置地址为 0x01**，所以网页默认地址为 1。
- 主站读写共用总线锁；`03` 每次读取最多 78 个，`06` 写单寄存器。成功读写更新本地缓存。
- 保持寄存器共 167 个，地址零基 `0..166`；网页支持 `03` 标准数量 1–125，兼容固件 78 个的限制。
- 未启用的轮询任务会读通用区 `0..77`、告警 `78..102`、系统 `106..166`，以及水状态 `0x6B..0x6C`。
- 头文件部分注释写水控制为十进制 103/104，但实际 MCP 常量和轮询实现均使用 **0x6B/0x6C（107/108）**。模拟器以可执行代码为准。未获得完整设备协议，其他地址只提供原始值，不推测含义。

| 内容 | 地址（零基 HEX） | 数据解释 |
| --- | --- | --- |
| 料塔 1 重量 | 0x02 / 0x03 | int32 kg，低 16 位字在前 |
| 料塔 2 重量 | 0x0E / 0x0F | 同上 |
| 料塔 3 重量 | 0x1A / 0x1B | 同上 |
| 料塔 4 重量 | 0x26 / 0x27 | 同上 |
| 灯光一 / 二 | 0x3B / 0x3C | 0–100%，0 关闭 |
| 保留位 | 0x69（105） | 原始寄存器可编辑 |
| 主水阀 | 0x6B（107） | 0 无状态，1 打开，2 关闭 |
| 水温 | 0x6C（108） | uint16 × 0.001°C，0–65.535°C |

每个寄存器在线上传输为大端字节，CRC 为低字节在前。料塔仅**字序**是低字在前，并非每个字节都小端。业务字段提供范围约束；通用表格允许所有地址填写 0–65535，以便模拟未知状态。示例值：水阀关闭、水温 25.500°C、灯光 60%/80%、重量 12000/8500/6400/15600kg，其余 0。

## 报文与存储

监视器展示时间、方向、完整 HEX（含 CRC）、地址、功能、读写地址、数量和原始读写值。有效但非法的请求返回异常：`01` 不支持的功能、`02` 地址越界、`03` 数量非法。监视器及导出日志仅保留最近 300 条。

全部 167 个寄存器与从机地址自动保存到当前浏览器 localStorage，也可 JSON 导入 / 导出。导入必须包含 `version: 1`、`address: 1..247` 和 167 个 uint16 数字组成的 `registers` 数组；文件整体校验成功才应用。连接时禁止导入以免改变在线地址。串口权限、自动响应开关、响应延迟、帧间隔和日志不持久化。

### 按接收空闲间隔划帧

所有功能码都先累积收到的数据，**接收空闲达到设定间隔后才校验整个帧**。`03` / `06` 不再按 8 字节提前解析，也不在噪声、粘连数据中搜索 CRC 合法的子帧。若同一间隔内收到多个请求，整段丢弃，不执行其中的写入。CRC 错误、地址无效、`03` / `06` 长度不等于 8 字节也整帧丢弃。超出 RTU 上限 256 字节时仅保留前 256 字节用于诊断，丢弃状态保持到空闲间隔结束，绝不把溢出后的有效尾部当新请求；下一帧重新开始。

页面提供「接收空闲帧间隔 / ms」（1–1000 整数），只能断开后修改。切换波特率会重设默认值：按当前固件 8N1 的 10 bit/字符计算 3.5 字符时间并向上取整，9600 为 4ms、19200 为 2ms；高于 19200 参考建议的 1.75ms 向上取整为 2ms。[Modbus 串行规范 V1.02](https://www.modbus.org/docs/Modbus_over_serial_line_V1_02.pdf) 定义 RTU 的 3.5 字符空闲边界和高速固定间隔建议。应用在每次接收和定时器触发时都检查实际经过的单调时钟时间，处理提前 / 延迟的定时器；断开连接会取消定时器和待解析数据。

**浏览器 / USB 无法提供线上的逐字节时间戳**，此处间隔是 JavaScript 观察到的数据块接收间隔，不能还原被驱动合并在一个块内的真实帧间空闲，也不能精确验证 t1.5 字符内间隔。合并数据选择整段丢弃，不猜测边界；USB 若把同一帧分片延迟超过当前窗口，也可能误判为不完整帧，需要适当调高页面间隔。调高可能合并短间隔的相邻请求，请以实际设备 / 适配器表现设置。浏览器后台节流会增加响应延迟，请保持页面前台。此工具用于固件联调，不作严格 RTU 时序认证。

## 验证

无需 ESP-IDF，使用 Node.js 运行协议和串口流测试：

```sh
node --test main/boards/waveshare/esp32-p4-nano/web/*.test.mjs
```

测试使用真实协议模块与模拟 Web Streams 串口，无法代替物理验证。硬件验收建议：读取水温和四塔重量（含负数）、修改两路灯光、水阀先读后写、错误从机地址、断开与重连、超时和适配器拔插。确认主站取得与页面设置一致的数值、写入回显正确，且下载口日志不混入业务总线。
